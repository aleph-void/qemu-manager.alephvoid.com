// Features

All of QEMU, in One Window

Build a VM from a hardware list, start it, and watch it boot in an embedded console. QEMU Manager writes the command line, supervises the helpers and keeps every VM in its own folder.

18 Guest Architectures

x86, ARM, RISC-V, POWER, MIPS, LoongArch, IBM Z, SPARC, m68k, Alpha and PA-RISC. Pick the machine type and CPU model from the lists your installed QEMU reports, with descriptions, or type your own.

A Real Hardware List

Add and remove devices the way Proxmox does: CPUs and memory, BIOS or UEFI, virtio, NVMe, SATA, IDE and USB disks, ISOs, boot order, sound cards, serial ports and host USB devices.

UEFI & TPM 2.0

Give a VM a virtual TPM emulated by swtpm, for Windows 11 or BitLocker. TPM keys and UEFI variables live in the VM's folder and carry over to clones.

Snapshots That Include Memory

Snapshot a running VM and its memory is saved too, so restoring resumes exactly where it was, even after a shutdown. Snapshots cover every qcow2 disk plus the UEFI variable store.

Full & Linked Clones

Full clones copy every disk. Linked clones are instant copy-on-write overlays on the original disks, so ten test machines cost almost no space.

OVA / OVF Appliances

Import appliances from VMware, VirtualBox and other tools. Manifests are checked; CPUs, memory, disk controllers, NICs, MACs and UEFI are mapped; disks convert to qcow2. Exports round-trip exactly.

Hardware Acceleration

Uses KVM on Linux, Hypervisor.framework on macOS and WHPX on Windows automatically when the guest matches the host CPU, and falls back to TCG emulation when it doesn't.

Embedded Console

An in-app display built on noVNC, with a fresh random VNC password for every boot. Prefer a native QEMU window or headless mode? Both are one setting away.

PCI & USB Passthrough

Pass a GPU or other PCIe device to a VM with VFIO on Linux. The app shows each device's driver and IOMMU group and tells you what to fix before it can be passed through.

Shared Folders

Share host folders with the guest over virtio-fs (Linux hosts) or 9p (Linux and macOS hosts). The app shows the mount command to run in the guest.

Networking That Fits the Host

User-mode NAT with port forwarding everywhere, bridged and TAP networking on Linux, TAP-Windows adapters on Windows and vmnet on macOS. Only modes your host supports are offered.

The Command Line, Visible

See the exact QEMU command line for any VM and add your own extra arguments. Start, pause, resume, reset, shut down or force stop over QMP, with live status and the QEMU log.

How It Works

QEMU Manager doesn't replace QEMU. It drives the QEMU you have installed, keeps each VM in a self-contained folder, and talks to the running machine over QMP.

1

Your QEMU

The app finds QEMU on your PATH and in standard install locations, reads which machines and CPUs it supports, and can help you install or update it.

  • Use your package manager's build
  • Or point it at a custom folder
2

Portable VM Bundles

Every VM is a folder holding vm.json, its disks, UEFI variables and TPM state. Copy it to another machine, back it up, or keep it in a synced drive.

  • No hidden database
  • Plain qcow2 disks
3

Supervised Processes

QEMU, swtpm and virtiofsd are spawned directly, never through a shell. VNC and QMP listen only on loopback or a private socket.

  • Crash and exit handling
  • Password-protected console

// FAQ

Frequently Asked Questions

Does QEMU Manager include QEMU?

No. QEMU is a separate program (GPL-2.0) that QEMU Manager runs as an external process; it is not linked or distributed with the app. Install it with your platform's package manager (see Requirements), and the app's QEMU page can help you install or update it.

Which host operating systems are supported?

macOS (Apple Silicon and Intel), Windows (x64 and ARM64) and Linux (x64 and ARM64). Some features depend on the host: PCI passthrough and virtio-fs are Linux-only, 9p shared folders need a Linux or macOS host, and TPM 2.0 is unavailable on Windows hosts because QEMU's Windows build has no TPM emulator backend.

Can I run Windows 11 in it?

Yes. Windows 11 needs UEFI firmware and a TPM 2.0. Install swtpm on a Linux or macOS host, choose UEFI and add a TPM in the VM's hardware list. On an x86-64 host with KVM, Hypervisor.framework or WHPX it runs with hardware acceleration.

Will it be fast, or is everything emulated?

When the guest architecture matches your CPU, QEMU Manager picks the host's accelerator automatically: KVM on Linux, Hypervisor.framework on macOS, WHPX on Windows. Other architectures run under TCG emulation, which is slower but works everywhere.

Can I bring my VMware or VirtualBox machines over?

Yes, export them as OVA or OVF and import them. QEMU Manager checks the manifest, maps CPUs, memory, disk controllers, NICs, MAC addresses and UEFI, and converts the disks to qcow2. It can also export OVAs with stream-optimized VMDK disks and a SHA-256 manifest.

Where are my VMs stored?

Each VM is a folder (a "bundle") holding vm.json, its disks, UEFI variables and TPM state. Nothing is kept in a hidden database, so you can back up, copy or move a VM like any other folder.

How does licensing work?

Buy once from the Aleph Void Store and you get a license key that works on macOS, Windows and Linux, on up to 10 machines. The key is checked with Gumroad the first time, then periodically; the app keeps working offline for weeks between checks, and a network hiccup never locks a running session.

Does it collect any data?

No analytics or telemetry. The app only goes online to verify your license key with Gumroad and, when you ask it to, to check for QEMU updates. See the Privacy Policy.

How do I report a bug?

Open an issue on our GitHub issue tracker, or see the Support page. Include your host OS, QEMU version, the guest architecture and the steps to reproduce.
